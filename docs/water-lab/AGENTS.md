# Water Lab progress documentation

For work under `docs/water-lab/`, maintain the visual progress record alongside implementation.

- For each completed phase or material visual revision, capture the existing UI before editing when possible and the checked result afterward. Do not recreate missing historical screenshots or imply that a screenshot was taken earlier than it was.
- Add a dated record under `progress/YYYY-MM-DD/` and link it from `progress/README.md`. Use the user's Asia/Seoul date for the record and preserve any trustworthy capture timestamp separately.
- Include the source commit, phase, device/renderer, visible configuration/settings, problem/change/result, checks, unresolved items and next action.
- Preserve original screenshots. Add captions and a `captures.json` manifest with dimensions and SHA-256 hashes. Validate image paths and hashes before committing.
- Keep software screenshots, design renders and actual physical-build photographs explicitly labeled. Physical photos and test measurements must come from actual supplied/verified evidence.
- Report GPU, browser, Android and physical checks separately. A Canvas capture cannot substantiate WebGL rendering or vessel performance.
- Update phase status and changelog with meaningful progress. A small text-only correction does not require a new gallery.

See `progress/README.md` for the record format. These documentation tasks should proceed within the user's existing authorization for the phase.
